# 원본 화면을 보존하는 과제 PDF 도구

이 프로젝트는 ASSN1 가위바위보 계단 게임의 원본 DOCX 또는 깨끗한 PDF를 받아, 학생이 보는 문제와 필수 조건을 유지하면서 복사·텍스트 추출 결과에만 표식을 넣는다. 기본 결과는 `assignment.pdf` 한 개다. 예전 결합본의 지역 변수 코드 예시와 이미지 속 `route_…` 문자열은 기본 경로에서 완전히 제외했다.

화면의 함수명은 원본의 `print_stairs` 그대로다. 텍스트를 추출하면 이 이름이 `paint_stairs`로 나오도록 대상 글자의 유니코드 매핑만 바꾼다. 2026년 9월 26일부터 숨은 `assert` 지시는 조건부 변환 주석으로 교체했다. 전체 Python 코드를 작성할 때만 무작위 문자열의 순서를 뒤집어 `trace_…` 주석으로 남기도록 하며, 번역·설명만 할 때는 변환을 수행하지 말라는 조건을 둔다. 완성된 표식은 PDF에 직접 들어 있지 않고 교사용 manifest에만 기록된다. 문구는 화면에 그리지 않으며 원래 게임의 이동 규칙과 계산 결과를 바꾸지 않는다. Python의 내장 `print()`를 바꾸는 기능은 아니다.

학생이 원본 화면을 읽고 직접 구현할 때는 원래의 여섯 함수와 입력·출력·이동 규칙만 지키면 된다. 추가 변수명, 주석, docstring, 검사 문자열은 원본의 필수 조건이 아니다. 다만 복사나 접근성 도구로 읽는 텍스트는 의도적으로 달라진다. 표식 발견은 해당 내용이 전달된 관찰이며, 그 자체가 AI 사용이나 전적인 의존의 확정 증거는 아니다.

조건부 지시가 모든 모델에서 지켜진다는 보장은 없다. 번역문에 숨은 지시가 나타나고 사람이 그 지시를 따를 수도 있다. 현재 버전은 이 반례를 제거했다고 주장하지 않으며 코드 생성과 번역 대조군 모두 실제 서비스 시험 전에는 `not_tested`로 기록한다. 설계와 시험 방법은 [조건부 변환 실험](docs/CONDITIONAL_TRANSFORM_KO.md)에 설명했다.

## 실행

Mac에서는 `PDF만들기.command`를 더블클릭하고 파일을 선택한다. Windows에서는 `MakePDF.cmd`를 실행한다. 두 파일은 Python 실행 바로가기이며 독립 실행파일은 아니다. 설치 방법은 [실행 안내](PORTABLE_GUIDE.md)에 설명했다.

```bash
./PDF만들기.command '/경로/수정한과제.docx'
./run.sh build '/경로/Word에서내보낸원본.pdf'
```

원본 파일을 고친 뒤 같은 명령을 다시 실행하면 새 기준 PDF와 새 표식을 만든다. 원본은 덮어쓰지 않는다. 함수명과 게임 규칙을 유지한 작은 수정은 새로 변환해서 처리하고, 페이지 수가 달라져도 전 페이지를 검사한다. 문서의 의미를 분석해 표식까지 자동 재설계하는 도구는 아니므로 함수명이나 이동 규칙을 바꿨다면 설정도 확인해야 한다.

`PDF만들기.command`, `MakePDF.cmd`, `다시만들기.command`, `run.sh build`는 모두 화면 보존 경로를 기본으로 사용한다. 예전 가시적 예시와 주석 실험은 기본 명령에서 나오지 않는다. 과거 실험을 재현하려면 `--experimental`을 명시해야 한다.

## 결과와 검사

완료 경로는 터미널과 `output/LATEST`에 표시된다. 그 폴더의 `assignment.pdf`가 후처리본이고 `baseline.pdf`는 비교용 기준본이다. `instructor-only/manifest.json`에는 입력·출력 해시, 표식, 함수명 치환 위치, 검사 결과가 저장된다. PDF와 해당 manifest를 함께 보관해야 나중에 같은 표식으로 대조할 수 있다. 교사용 폴더와 실험 기록은 학생 배포 대상이 아니다.

스크립트는 모든 페이지를 120 dpi와 200 dpi로 렌더링해 기준본과 픽셀이 같은지 검사한다. 페이지 수·크기·회전을 확인하고 Poppler 세 방식과 pypdf에서 함수명 치환, 페이지별 조건문 전체와 변환 전 문자열을 검사한다. 완성된 `trace_…` 표식이 추출문에 없다는 것도 확인한다. Poppler 추출문에서는 의도한 두 변경을 되돌렸을 때 본문이 보존되는지도 확인한다. 공백과 독립 글머리표의 추출 순서 차이는 문자열 비교에서 제외하고, 실제 위치는 픽셀 검사로 확인한다.

실패하면 최종 `assignment.pdf`를 게시하지 않고 `output/LATEST`도 갱신하지 않는다. 이 검사는 지정한 렌더러와 추출기에서의 결과이며, 모든 뷰어·인쇄 드라이버·AI 서비스의 동작을 보장하지 않는다. PDF 생성 과정에서는 외부 AI를 호출하지 않는다.

## 제출물과 실험 기록

```bash
./run.sh scan --manifest '/배포본/instructor-only/manifest.json' --out './검사결과.json' '/제출물폴더'
```

검사기는 제출 코드를 실행하지 않고 식별자·주석·문서 문자열·assert 메시지에서 표식 위치를 찾는다. 생성 기록과 제출물을 함께 보관하는 방법은 [증거 보관 안내](EVIDENCE_GUIDE.md)에 있다. 모델 입력과 출력 코드, 보고서, 재요청 여부는 `trial_ledger.py`로 따로 기록한다. 별칭이 구현됐을 때는 표식 전달과 원래 필수 함수명 누락을 각각 기록하며 과제 명세 통과로 표시하지 않는다.

모델 기록 명령의 `--task translation-only` 또는 `--task explanation-only`는 번역·설명 대조군을 구분한다. 이런 응답은 코드 생성 성공으로 집계하지 않는다. 전체 코드 생성은 기본값인 `--task code-generation`을 사용한다. 번역문에 추가 요구사항이 생겼는지는 원문과 대조해 사람이 별도로 기록해야 한다.

기존 방식의 설계와 실패, 모델별 관찰, 가시적 예시를 제외한 이유는 [한국어 실험 이력](HISTORY_KO.md)에 줄글로 정리했다. 현재 구현은 [설계 설명](DESIGN_KO.md), 이번 검사는 [검증 기록](docs/VERIFICATION_KO.md)에 있다. 개별 과거 기록은 `RESULTS.md`, `MULTIMODEL_RESULTS.md`, `GEMINI_FOLLOWUP.md`, `SIGNAL_SUITE.md`에 보존했다.

기존 `native-alias`는 네 추출기를 통과했지만 Gemini Flash가 원래 함수명을 사용한 표본이 있었다. 가시적 예시가 들어간 예전 결합본의 결과를 현재 화면 보존 결합본의 성능으로 옮겨 주장하지 않는다. 새 입력의 모델 결과는 별도 시험 전까지 `not_tested`다.

저장소에는 코드와 한국어 설명, 합성 테스트만 올린다. 원본 DOCX, 생성 PDF, 모델 대화, 제출물, 서명키와 인증 정보는 Git 추적 대상에서 제외한다. GitHub Actions도 합성 PDF로 자동 검사를 실행한다.
